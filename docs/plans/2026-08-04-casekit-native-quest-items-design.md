# CaseKit native quest items — design

## Решение

StoryPack явно классифицирует каждый физический предмет:

- `quest` — нативный квестовый предмет, отображается в разделе заданий;
- `loot` — обычный предмет, остаётся полноценной добычей.

Для шага расследования контракт хранится в `action.item`. Для трофея — в
`trophyDefinition.item`. Отсутствующая или неизвестная классификация у
физического предмета является ошибкой компиляции.

## Контракт

```json
{
  "item": {
    "classification": "quest",
    "retention": "case"
  }
}
```

`retention`:

- `case` — улика может быть удалена после завершения дела;
- `permanent` — предмет остаётся навсегда.

Трофей `bird-feather` обязан иметь `classification: quest`,
`retention: permanent`, `weight: 0`.

Все дела переиспользуют один физический класс трофея:

- RU: `Трофей - Окровавленное перо`;
- EN: `Trophy - Bloodied Feather`;
- один item GUID, один signal, неограниченное число экземпляров;
- число уже собранных перьев хранится как baseline текущего дела.

## Runtime

Lua выбирает дело, контейнер и цель. Обычные предметы можно создавать через
Lua inventory API. Квестовые предметы Lua не создаёт: он отправляет
идемпотентный запрос в живой квестовый граф, а XML создаёт зарегистрированный
item class в алиасном inventory через `Inventory.CreateItems`.

В каждый момент активно одно дело. Генератор создаёт только реально
скомпилированные placement-ветки; произведения «все предметы × все контейнеры»
нет.

Сигнал выделяется на уникальный класс квестового предмета, а не на поселение,
цель, CaseVariant или экземпляр. Текущая production-сборка имеет три сигнала:
два документа и общее трофей-перо. Request-buff неперсистентный: после загрузки
Lua повторяет актуальный запрос. Защитный каталог погребения объединяет 293
ванильных и все скомпилированные пользовательские quest-item классы.

## Проверка

Статика доказывает схему, таблицы, маршрутизацию, генерацию signal ID выше 255 и
отсутствие ручного создания quest item. Live-canary доказывает появление в
разделе заданий, размещение в сундуке/на теле, отсутствие дублей и
восстановление после save/load.

Нерешённые вопросы: нет.
